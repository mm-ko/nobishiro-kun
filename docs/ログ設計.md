# ログ設計

## 現在の出力

| 出力元（`backend/app/`配下）    | 内容                                                                                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shared/exceptions/__init__.py` | 共通ハンドラーで4xxをWARNING、5xxをERROR。`request_id`、method、path、status、code、例外の型名のみを記録                                                   |
| `features/health/repository.py` | DB接続失敗をWARNINGで記録。例外の型名のみ                                                                                                                  |
| `features/payment/service.py`   | Stripe API版の不一致、アプリユーザーに紐づかないイベントのスキップをWARNINGで記録。後者はイベントIDを含む。二重active契約の後発解約もWARNINGで契約IDを記録 |
| `features/usage/service.py`     | Memcached接続不可・カウンター消失時に、レート制限せず通した旨をWARNINGで記録。ユーザーID・キーは記録しない                                                 |
| `main.py`                       | 開発用固定ユーザーの有効化を起動時にWARNINGで通知                                                                                                          |
| `core/logging.py`               | 起動時に`APP_ENV`を見て、ログのレベル・アクセスログ・依存ライブラリのログを切り替える（#157）                                                              |

共通エラーの`request_id`はエラー応答ごとに生成し、応答とログで共有する。分析処理IDとは別物。成功応答を含む全リクエストの追跡・処理時間計測は未整備。

ログの環境別の切り替えは`core/logging.py`の`configure_logging`で行い、`main.py`の起動時に`APP_ENV`を渡して呼ぶ（#157）。Uvicornの例外ログやHTTPクライアント等のログは別系統であり、共通ハンドラーだけで全文の漏えいを防げるとは扱わない。

## 開発／本番の出し分け（#157で実装）

`APP_ENV=development`を開発、それ以外（既定値の`production`）を本番として扱う。

| 対象                  | 開発                                                                     | 本番                                                                         |
| --------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| アプリの基本レベル    | INFO以上                                                                 | WARNING以上（当初の方針のINFO以上から変更）。常時DEBUGを使用しない           |
| WARNING／ERROR        | 現行のエラーコード・型名・追跡IDを記録                                   | 同左。個人情報を含む例外メッセージ・トレースをそのまま出さない               |
| HTTP／SQL等の詳細ログ | 依存ライブラリ（httpx・Stripe・Firebase・SQLAlchemy等）はWARNING以上のみ | 同左                                                                         |
| アクセスログ          | Uvicorn標準のアクセスログを使用する。クエリの除去は今回の対象外          | 出さない（生のURL・クエリを残さないため、アクセスログをWARNING以上に絞る）   |
| 出力先・保存          | 標準出力／標準エラー。共有時に内容を確認                                 | 同左を収集する構成を検討。保管期間・閲覧権限・ローテーション・通知先は未実装 |

## 出力禁止情報（両環境共通）

- 画像・base64・リクエスト／レスポンス本文のダンプ・AIの入出力全文
- 氏名・メールアドレス・答案内容などの個人情報・顧客データ
- 認証トークン、Cookie、パスワード、APIキー、Webhook署名、DB接続文字列、設定値全体
- 外部サービスの自由文エラー、検証エラーの入力値、任意クエリ文字列（開発のUvicorn標準アクセスログはクエリを含むため、開発の出力は共有時に内容を確認する。本番はアクセスログを出さない）

Frontendも同じ禁止範囲とする。ユーザー向けエラー表示と開発者用ログを分け、API応答やフォーム値を`console.log`へ出さない。

共通ログのpathは現在`request.url.path`の生値である。今後、個人情報をURLパスに持つAPIを追加する場合は、ルートテンプレートへの置換等が必要。現状の実装が任意のパスを安全にマスクするわけではない。

## 検証・残事項

`backend/tests/shared/test_shared_exceptions.py`で、応答とログのID一致、入力値・クエリ・内部例外内容を残さないことを確認する。これはアプリ共通ログの確認で、サーバー／依存ライブラリのログ検証を代替しない。

`backend/scripts/verify_stage_a.py --review`は読み取り内容を表示するため、本設計の通常ログとして使用しない。実答案で実行した出力を保存・共有しない。AI回帰確認は[テスト設計書](テスト設計書.md)の方法に従う。

`backend/tests/shared/test_logging_config.py`で、開発・本番それぞれのログのレベル、アクセスログ、依存ライブラリのレベルを確認する。

今後は、開発のアクセスログのクエリ除去、成功時の計測、出力先・保管期間・アクセス制御を実装担当と決める。文書作成だけで対応済みにはしない。
