# テスト設計書

## 方針・実行方法

BackendはPython 3.13・pytest、FrontendはNode.js 22・Vitest＋React Testing Library（jsdom）。機能の振る舞いと境界値を確認し、実装詳細だけをなぞるテストを避ける。CI（#43）は見送りとし、以下のチェックを手元で実行する。

Backendディレクトリで、既存の依存導入済み環境から実行する。

```text
python -m pytest
python -m ruff check .
python -m ruff format --check .
```

Frontendディレクトリで実行する。

```text
npm test
npm run lint
npm run format:check
npm run build
```

単体テストにenvファイル・鍵・実DB・実AIを使わない。Backendの`tests/conftest.py`はimport前に接続設定を空にし、固定ユーザーを無効化し、socket・psycopgの実通信を遮断する。SQLiteやモックでの結果はPostgreSQLのロック・並行実行の実証とは分ける。セットアップ・Dockerでの隔離実行は[Backend README](../backend/README.md)を参照。

## AIの回帰確認

通常テストはモックによる処理確認であり、実モデルの精度保証にはならない。モデル・プロンプト・Provider設定変更時は次の代表ケースを同じ入力で比較する。

| 工程     | 代表ケース                                               | 合格の観点                                                           |
| -------- | -------------------------------------------------------- | -------------------------------------------------------------------- |
| Stage A  | 表裏2枚、読めない文字、空欄、途中式、同じ問題番号        | 見えていない内容を補わず、画像ごとの区別・unknown・nullを保持する    |
| Stage B  | わり算、筆算、対象外、単元不明、空欄、書き写し、全問正解 | 単元と問題参照が一致し、根拠不足の原因を断定しない                   |
| コメント | 誤答あり、全問正解、形式不正                             | 今回の答案に即し、断定や過去傾向の捏造がなく、長さ等のschemaを満たす |

`backend/tests/ai_analysis/stage_b_cases.py`の架空データと`backend/scripts/verify_stage_b.py`が既存の比較入口。Stage Aには`backend/scripts/verify_stage_a.py`がある。実API実行は費用と外部送信を伴うため単体テストから分離し、この文書作成では実行しない。

回帰実施時は利用許諾済み・個人情報のない入力を用い、実行日、コード版、モデル、Provider、ケースID、合否、呼出回数、所要時間、課題の要約を記録する。APIキー・画像・AI入出力全文は記録しない。`--review`は内容を表示するため実答案では使用せず、必要なら架空データのみを目視確認する。全ケース合格でも未検証の単元・画像品質まで一般化しない。

## 結合・手動テスト

1. Firebaseの実環境で、未ログイン・期限切れ・他ユーザーの履歴へのアクセスを確認する。
2. スマートフォン幅で画像選択→任意トリミング→Stage A→修正・得点入力→Stage B→履歴・ランキングを確認する。リロード・戻る・二重送信・失敗後の再操作も確認する。
3. AI文字列にHTML風の架空文字を含めてもテキストとして表示されること、外部URLを扱う箇所の検証を確認する。
4. Frontendの利用状況・Checkout接続後、Stripeテストモードで成功・キャンセル・失敗・Webhook遅延／再送を確認する。成功画面だけで有料扱いにしない。
5. 開発／本番設定ごとに、アプリ・サーバー・依存ライブラリのログへ禁止情報が残らないことを確認する。

実行結果にはコマンド・実行環境・合否・未確認項目を残す。失敗や未実装を除外して「全機能確認済み」と報告しない。
