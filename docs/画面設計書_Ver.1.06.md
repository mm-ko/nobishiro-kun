## 2. プロジェクト概要

PRD・機能要件を参照。本ドキュメントは機能要件を画面単位に落とし込み、Frontend担当者が並行実装するための画面ID、画面遷移、スマートフォン向けワイヤーフレームを定める。画面IDはVer.1.03の付け方に準拠する。設定画面と認証の追加機能はMVP対象外とし、学習履歴はホーム画面だけに表示する。利用者向けの表記は「解析」ではなく「分析」に統一する。

## 3. 前提・確定事項

- MVP対象は小学3年生の算数の単元テスト（先生による採点済み・児童の解き直し前）に限定する
- MVP対応単元は「わり算（あまりのあるわり算を含む）」「たし算とひき算の筆算」とする
- 画面IDの付け方はVer.1.03に準拠し、同じ画面内の表示違いは別画面IDに分けず、画面の状態として扱う
- 学習履歴はUI-002（ホーム）だけに表示し、UI-007（分析結果）には表示しない
- 苦手単元ランキングは独立画面とせず、UI-002（ホーム）にカードとして表示する
- UI-010（設定）はMVP対象外とする
- 認証はログイン・新規登録・ログアウトだけを実装し、パスワード再設定・メール認証・退会機能はMVPでは採用しない
- Stage Bは、UI-006で保護者が確認・修正したデータだけを使用する
- 対象外・判定困難はUI-007の別状態として案内し、ボタン操作でUI-002（ホーム）へ戻る
- 対象外・判定困難の結果は、学習履歴・ランキングに保存せず、利用回数にも含めない
- 有料プランは月10回まで（無料の2回を含む）とし、日本時間の暦月で数える。上限に達した場合は、契約の有無にかかわらず、その月は分析を開始できない（2026/10/24 決定、#23・#37）
- UI-003でアップロードできる画像は最大2枚、1枚10MB、合計20MBまでとする（容量の上限は、Issue #27の技術検証で確定する。変わった場合は本書を更新する）
- UI-003の「トリミングへ進む」ボタンは、画面の下に固定して表示する（講師コメント：ボタンは下側のほうが操作しやすい）
- UI-003には「戻る」ボタンを設けない。ホームへ戻るときは、ブラウザの「戻る」を使う（Issue #87）
- UI-003の「差し替え」「削除」は、共通のButtonを使わず、この画面専用の操作とする（Issue #87）
- UI-006の任意メモ欄は採用しない
- UI-005とUI-006Bは分析中の表示状態であり、独立したURLを持たせない
- UI-005とUI-006Bに、途中離脱・再読み込み時の案内を表示する
- UI-005とUI-006Bの待ち時間は、「言葉の切り替え」「3段階のゲージ」「のびしろくんの動き」で見せる。「〇%」の数字は表示しない
- UI-005とUI-006Bの表示は、実際の処理の進み具合とは連動せず、時間で切り替える。処理が早く終わった場合は、すぐに次の画面へ進む。処理が長引いた場合は、3つ目の段階を「進行中」のまま待ち、「完了」にするのは結果が返ったときだけとする
- UI-005とUI-006Bの言葉とゲージは、表示してから3秒で2つ目、6秒で3つ目へ切り替える。待ち時間の上限は120秒とする（Issue #88・#128）
- UI-006の確認画面は、初期値を全問「合っている」とし、違うところだけを選ぶ形とする。正誤が不明の問題、解答が読み取れなかった問題は、選択・入力するまで進めない
- UI-005／UI-006Bのワイヤーフレームに、エラー時の表示状態を追加する
- 利用者向けの表記は「解析」ではなく「分析」に統一する
- 苦手単元ランキングはAPI仕様書を正とし、低い値を上位、同率は同順位、同順位内は単元コード順とする
- ランキング対象データがない場合の表示文言は、該当IssueでFrontend担当者が検討する
- 決済方式と決済結果の詳細は、Backend担当者の方針決定後に反映する

- 苦手単元ランキングは低い値を上位に表示する
- 同率は同順位とし、同順位内は単元コード順で表示する
- ランキングがない場合の表示文言は、該当IssueでFrontend担当者が検討する

- JPEG、JPG、PNGに対応する
- アップロードできる画像は最大2枚とする
- 容量は1枚10MB、合計20MBまでとする（上限は、Issue #27の技術検証で確定する。画面の注意書きとBackendの検証は、同じ値を使う）
- 画面の上から順に、「STEP 1/2と見出し」「のびしろくんの吹き出し」「選んだ画像の枠」「カメラで撮影」「画像を選ぶ（下に小さな注意書き）」「トリミングへ進む」を並べる
- のびしろくんの吹き出しには、「問題番号・問題文・解答・採点結果が読めるように撮影してください。」と表示する。のびしろくんの画像がない間は、丸のプレースホルダーを使用する
- 選んだ画像の枠は、0枚のときは「ここに並びます」を表示する。選んだあとは、画像1・画像2を横に並べ、画像ごとの下に「差し替え」「削除」を表示する
- 「カメラで撮影」と「画像を選ぶ」の2つのボタンは、選んだ枚数にかかわらず同じものを表示する。「もう1枚追加」のボタンは設けない
- 「JPEG・JPG・PNG／最大2枚／1枚10MB・合計20MB」の注意書きは、「画像を選ぶ」ボタンの下に、小さな文字で表示する
- 「トリミングへ進む」は、画面の下に固定する。画像が2枚でも、隠れないようにする
- 画像が0枚の場合は、「トリミングへ進む」を押せない表示にする。1枚以上で押せる表示にする
- 下に固定したボタンは、スマートフォンの下の余白（ホームの線）に重ならないようにする。上の余白も、スマートフォンの状態バーに重ならないようにする
- 「差し替え」「削除」は、画像に付く小さな操作とする。タップできる大きさは44px以上とし、「削除」は赤の枠・赤の文字とする。共通のButtonは使わず、この画面専用の操作とする（Issue #87）
- 「戻る」ボタンは設けない。ホームへ戻るときは、ブラウザの「戻る」を使う（Issue #87）
- 画像やbase64データをログまたはlocalStorageへ保存しない

### UI-005 分析中（Stage A）

通常状態：

~~~text
┌──────────────────────┐
│    内容を確認しています   │
│          ◯           │
│       のびしろくん       │
│ 画像を読み取っています     │  ← 時間で切り替える
│      ● ─ ○ ─ ○       │  ← 3段階のゲージ
│ 画面を閉じずに            │
│ そのままお待ちください     │
└──────────────────────┘
~~~

エラー状態（仮）：

~~~text
┌──────────────────────┐
│ 分析を完了できませんでした │
├──────────────────────┤
│ 通信状況をご確認のうえ、   │
│ もう一度お試しください     │
│                      │
│ [もう一度試す]             │
│ [トリミングへ戻る]         │
└──────────────────────┘
~~~

- 利用者向けには「解析中」ではなく「分析中」と表示する
- UI-005は独立したURLを持たない表示状態とする
- 言葉は、時間で次の順に切り替える：「画像を読み取っています」→「採点を確認しています」→「分析しています」
- 3段階のゲージ（丸3つ）は、言葉の切り替えと同じタイミングで進める。「〇%」の数字は表示しない
- 言葉とゲージは、実際の処理の進み具合とは連動しない。時間で進める
- 処理が早く終わった場合は、ゲージが途中でも、結果が返ったらすぐにUI-006へ進む
- 処理が長引いた場合は、3つ目の丸を「進行中」のまま止めて待つ。3つ目が「完了」になるのは、結果が返ったときだけとする
- のびしろくんには、ゆれる・はねるなどの簡単な動きを付ける。端末の「動きを減らす」設定がオンの場合は、動かさない
- 言葉が切り替わるときは、スクリーンリーダーでも読み上げられるようにする
- 表示してから3秒で2つ目、6秒で3つ目の言葉へ切り替える。待ち時間の上限は120秒とし、上限を超えた場合は、エラー状態を表示する（Issue #88・#128）
- 分析中の二重送信を防止する
- 途中離脱または再読み込みを行うと、分析が中断される可能性があることを案内する
- エラー時は再試行またはUI-004へ戻る操作を表示する
- エラーの詳細文言は、レート制限仕様と合わせて確定する
- 分析の開始時に月の上限に達していた場合（`403 MONTHLY_LIMIT_REACHED`）は、エラー状態に「今月の分析回数の上限に達しました。来月1日から、また分析できます。」と表示する
- このときは［もう一度試す］［トリミングへ戻る］を表示せず、［ホームへ戻る］だけを表示する（やり直しても分析できないため）
- 分析の開始時に契約が必要だった場合（`403 PLAN_REQUIRED`）は、エラー状態を表示せず、すぐにUI-008（有料案内）へ移動する。移動するときは今の画面の履歴を置き換え、UI-008で「戻る」を押したときにUI-005へ戻らないようにする


### UI-006 読み取り結果の確認・修正

~~~text
┌──────────────────────┐
│ AIの読み取りを確認      │
│ テストと見比べて、       │
│ 違うところだけ押してください│
│ 得点 [__] ／ 満点 [__] │
├──────────────────────┤
│ 1:1(1)  読み取り：6     │
│ 解答 [○合っている] [×違う]│  ← 初期値は「合っている」
│ 違う時：[実際の解答___]   │
│         [実際は空欄だった] │
│ 正誤 [○合っている] [×違う]│  ← 初期値は「合っている」
│ 違う時：[○正解][×不正解] │
├──────────────────────┤
│ 1:2  正誤が読み取れません │
│ 正誤 [○正解] [×不正解]   │  ← 未選択。選ぶまで進めない
├──────────────────────┤
│ 1:3  解答が読み取れません │
│ 解答 [実際の解答___]     │
│      [実際は空欄だった]   │  ← 未入力。入力するか「実際は空欄だった」を選ぶまで進めない
├──────────────────────┤
│ 問2、問3…              │
│ [確認完了して分析する]   │
└──────────────────────┘
~~~

- 画面の上に、「テストと見比べて、違うところだけ押してください」と案内する
- 問題ごとに、読み取った解答内容と正誤を表示する。問題番号は、「画像番号:問題番号」（例：1:1(1)）で表示する
- 解答内容と正誤は、それぞれ独立して確認・修正できるようにする
- 初期値は、全問「合っている」とする。読み取りが違う問題だけを、保護者が「違う」にする
- 「違う」を選んだ場合は、解答内容では「実際の解答」を入力し、正誤では「正解／不正解」を選ぶ。もう一度押すと、「合っている」に戻せる
- 正誤が不明（unknown）の問題は、初期値を「合っている」にせず、「未選択」として表示する。「正解／不正解」を選ぶまで進めない
- 解答が読み取れなかった（null）の問題は、「未入力」として表示する。実際の解答を入力するか、「実際は空欄だった」を選ぶまで進めない
- 解答の入力欄とあわせて「実際は空欄だった」ボタンを表示する。選択した場合は、確認済みの解答を空文字として扱う
- 「違う」を選んで「実際の解答」を入力する欄が空のままで、「実際は空欄だった」も選ばれていない場合は、進めない
- 進めない理由は、どの問題の何が足りないかが分かるように表示する
- 条件付きで表示される入力項目は、同じ問題カード内に表示する
- 得点と満点の入力欄を表示する。得点は、読み取った値を初期表示する
- 任意のメモ欄は設けない
- UI-006の確認・修正を完了とする条件のうち、正誤が不明・解答が読み取れなかった問題を選択・入力済みであることは決定済みとする。そのほかの条件は未確定事項として扱う
- 確認完了後、UI-006Bへ進む

- コメントは、次の2つのカードに分けて表示する（Issue #134）。本文の文字は変えず、区切り方と見た目だけを変える
  - カード1：タイトル（黄色 `--color-accent` のマーカー）と、本文の最初の「。」までの1文（労い）。労いの1文は本文のフォントで、太字にしない

  - 文の区切りはAIへの指示（「最初は労い」など）に頼っているため、AIの書き方がずれた場合はマーカーの位置がずれることがある

## 7. 共通仕様

| 共通仕様 | 適用画面 |
|---|---|
| 通信中・分析中は送信ボタンを無効化し、二重送信を防止する | 送信処理のある画面（UI-001、UI-004、UI-006、UI-008、UI-009） |
| エラーは日本語で表示し、利用者が次に行う修正・再試行方法を案内する | エラー表示のある全画面。特にUI-005のエラー状態、UI-006Bのエラー状態 |
| レート制限時は、時間をおいて再試行するよう案内する | UI-005のエラー状態、UI-006Bのエラー状態。回数・時間の詳細は未確認事項とする |
| スマートフォン幅で横スクロールを発生させず、指で操作しやすい大きさを確保する | 全画面 |
| 入力欄にはlabel、画像にはalt、操作にはbuttonを使用する | 入力・画像・操作要素を持つ全画面 |
| 正解・不正解、成功・失敗を色だけで区別せず、文字と記号を併記する | UI-006、UI-007、UI-009 |
| ログアウト後はUI-001へ移動し、保護された画面を再表示できないようにする | 認証後の全画面（UI-002〜UI-009） |
| 途中データが失われる可能性がある場合は、離脱・再読み込み前に警告する | UI-003、UI-004、UI-005、UI-006、UI-006B |
| 利用者向けの表記は「解析」ではなく「分析」に統一する | 全画面 |
| 画面の下に固定するボタンは、スマートフォンの下の余白（ホームの線）に重ならないようにする。上の余白も、状態バーに重ならないようにする | UI-003（ほかの画面で下に固定するボタンを使う場合も同様） |
| 動きのある表示は、端末の「動きを減らす」設定がオンの場合は動かさない | UI-005、UI-006B |

離脱・再読み込み時の警告は、アプリ内の画面移動とブラウザーの再読み込み・タブを閉じる操作を対象とする。ブラウザーやOSの強制終了など、警告を表示できない操作は対象外とする。途中データの復元はMVP対象外とし、失われた場合は再アップロードからやり直すよう案内する。

### 7.1 UIの言葉づかい

| 目的 | 使用する表現例 | 避ける表現例 |
|---|---|---|
| 成長 | できた単元、あと少し、伸びしろ | できていない、能力が低い |
| 行動 | 今日やってみよう、一緒に確認しましょう | 必ずやるべき、間違いだらけ |
| 不確かさ | 〜かもしれません、〜のようです | 理解できていません |
| 再試行 | 少し時間をおいてお試しください | 内部エラーや例外全文 |

「苦手単元ランキング」には、「ここから復習すると伸びやすい単元です」などの補足を添える。
