# 開発方針

本ドキュメントでは、チーム開発におけるドキュメント作成、担当、スケジュール、
Issue管理、環境構築、情報共有についての方針をまとめます。

内容に変更があった場合は、本ドキュメントを更新します。

## 4. Issue作成方針

MVPが確定したため、全体のIssue作成を開始します。

現段階では、まず必要な作業を洗い出してIssue化します。

画面設計・API設計・DB設計が固まった段階で、
必要に応じてIssueを実装しやすい粒度へ分割・修正します。

各Issueには必要に応じて以下を記載します。

- 作業内容
- 完了条件
- 担当者（Assignee）
- 関連するIssue
- 前提となるIssue

---

## 5. 環境構築

### フロント

9/23（水）までを目安に環境構築を行います。

フロント担当で環境構築用のIssueを作成し、作業を進めます。

環境構築時に以下も決定・記録します。

- ディレクトリ構成
- ファイル構成
- ファイル名
- 起動方法
- 必要なパッケージ

これらの情報は、フロント用READMEにも流用します。

### バックエンド

9/23（水）までを目安に環境構築を行います。

担当：ようこ

バックエンド環境構築用のIssueを作成し、作業を進めます。

### 環境構築時点での目標

この段階では、すべての外部サービスとの接続完了までは求めません。

まずは、

- フロントが起動できる
- バックエンドが起動できる
- チームメンバーが同じ環境を再現できる

状態を目標とします。

Firebase、AI、DB、キャッシュ、決済等の接続については、
必要に応じて別Issueとして進めます。

## 6. レビュー方針

主要な設計・ルールについては、
作成者だけで確定せず、チーム全員でレビューします。

直近では以下を予定しています。

- 9/22：画面設計レビュー
- 9/24：コーディング規約レビュー

レビュー後、必要な修正を反映して確定します。

## 7. 情報共有ルール

情報の置き場所を以下のように分けます。

### GitHub

決定事項や正式な情報を残します。

- 仕様・設計 → docs
- タスク → GitHub Issues
- 開発ルール → 各運用ドキュメント
- 進捗 → Issues / Projects

### チャット

以下の用途で使用します。

- 相談
- 確認
- 質問
- 連絡
- GitHub更新の共有

チャットで重要な内容が決定した場合は、
GitHubの該当ドキュメントへ反映します。
